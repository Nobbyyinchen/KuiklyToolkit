# Contributing

1. Do not add business models, private assets, internal endpoints, routing or analytics dependencies.
2. Public UI APIs must remain in `commonMain` and use Kuikly traditional DSL.
3. Add common tests for pure state or boundary logic.
4. Run JS tests and Android compilation before opening a pull request.
5. UI changes require Android, iOS and HarmonyOS manual verification evidence.
6. Keep API and behavior changes documented in `README.md` and `CHANGELOG.md`.
